# Optional Jev observation judgment

Item42 / issue #563 stacks on CUA orchestration PR #561. This adapter preserves the selected chat LLM and every existing approval boundary. It is off by default. It never grants input, coordinates, approval, Save, cancellation, or credential-read authority to a model.

## Official contract verified 2026-11-24

The official [documentation index](https://docs.typesafe.ai/llms.txt) links the [quickstart](https://docs.typesafe.ai/introduction/quickstart.md), [System One endpoint](https://docs.typesafe.ai/api/system-one.md), [model listing](https://docs.typesafe.ai/api/list-models.md), [errors](https://docs.typesafe.ai/api/errors.md), [JavaScript SDK](https://docs.typesafe.ai/sdk/javascript.md), and [confidence](https://docs.typesafe.ai/confidence.md). The machine-readable [OpenAPI document](https://api.typesafe.ai/openapi.json) reports API schema version **0.2.0**; this is not a model version.

The implementation uses `POST https://api.typesafe.ai/v1/systemone` with `Authorization: Bearer <main-only key>`. The request contains `model`, `state`, named `questions`, and image `assets`; the named `judgment` question has `type: choice`, instructions, and a criteria object keyed by trusted candidate IDs. The response contains the resolved model, identically named answer, selected choice, confidence, probabilities, and token usage. `GET /v1/models` requires authentication and reports account availability; it was not called with an account during implementation.

The model pin is **jev-1.14.0**. The official [models table](https://docs.typesafe.ai/models.md) lists that exact ID with text/image input, and the [model changelog](https://docs.typesafe.ai/changelog.md) dates Jev 1.14 to October 14, 2026. Moving aliases (`jev-latest`, `jev-preview`) are deliberately not accepted as resolved responses. PNG images require `TypeSafe-Danger-Zone-Images: true`, per OpenAPI and the [image documentation](https://docs.typesafe.ai/images.md). Image transmission requires a separate main-owned `imageTransmissionAuthorized: true` context flag. By default the request contains only observation metadata and summary, with no image, assets or image header. When separately authorized, the adapter sends only the existing explicit observation image; it does not capture another frame.

The JavaScript documentation references **@typesafe-ai/sdk v0.7.0**, including its [pinned client source](https://github.com/typesafe-ai/typesafe-sdk-js/blob/v0.7.0/src/client.ts). The SDK requires Node.js 22+, with zstd compression requiring 22.15+. No SDK dependency is installed: this adapter uses the documented JSON HTTP contract and Electron main's native `fetch`, `AbortController`, and response streams, with no compression. The repository pins Electron 43.1.1; type/build and mock fetch verification do not establish a live Electron-to-TypeSafe connection. A packaged Electron runtime/live authenticated request remains unverified.

## Main-only seam

`src/main/jevObservationJudgment.ts` exports `createJevObservationHook`, `JEV_MODEL`, `DEFAULT_JEV_CONFIG`, and the DI types. Config is `{ enabled, model, minSelectedProbability, timeoutMs }`, defaulting to `{ enabled: false, model: 'jev-1.14.0', minSelectedProbability: 0.95, timeoutMs: 2500 }`. Accepted thresholds are finite numbers in `[0.5, 1]`; timeouts are integer milliseconds in `[1, 5000]`.

The main-only caller supplies `getConfig`, asynchronous `getApiKey`, and `getObservationContext(conversationId)`. The context includes trusted current frame metadata, actual held-input count, cleanup completion, the run's abort signal, a question kind, instructions, and 2–32 main-owned candidates. Kinds are `candidate-selection`, `semantic-result`, and `reobserve`. Candidates are descriptions and IDs only, with no executable input or authority.

Network also requires `acquireJudgmentLease(conversationId, frameIdentity)` to return a main-owned release handle. This is a proposed integration contract: absence or refusal means zero network and existing LLM fallback. Main must reject competing input for the entire lease, without granting a permit. The returned lease includes pinned metadata, an abort signal, owner-aware `getCurrentFrame()`, and `release()`. The adapter combines lease/run/caller/timeout cancellation and uses that owner-aware getter without bypassing other guards. The handle is released only after the HTTP/body work actually settles, including after timeout/abort; returning a timeout to the graph does not release a still-running transport. Driver metadata alone does not provide this exclusion.

The graph invokes its optional hook only after a model-explicit `observeEditorWindow` invocation has completed, before conversion into visual evidence. It supplies a clone of that result. A validated advisory is included in the observation ToolMessage consumed by the existing LLM. A validated reobserve choice deterministically withholds that observation image from further target selection and adds guidance requesting a separate explicit observation. A sufficient choice retains the normal image path; it does not establish visual correctness, task success or authority. Uncertain/invalid results retain the original image and existing LLM path. No branch executes input or automatically observes. Main configuration/credential wiring still depends on the separately owned backend contract; an unconfigured hook leaves behavior unchanged.

## Validation and limits

The adapter checks session/run/window/frame/layout/content identity, captured timestamp and age (<5 seconds), held count zero, cleanup complete, and active run before key access/network and after awaits. It snapshots trusted candidates and instructions, rejects duplicate/unknown/missing IDs, checks resolved model and response shape, verifies each probability lies in `[0,1]`, the distribution sums to approximately one, and the selected candidate has maximal probability. Low selected probability, stale evidence, disabled config, missing key, lease refusal, timeout, cancellation, schema failure, HTTP failure, or an opaque exception returns `null` and preserves the existing LLM path.

At most three requests are attempted per session/run, then the existing LLM path is retained. One request is attempted per explicit frame identity. There are no retries or redirects. Input PNG text is limited to 2,000,000 characters and streamed response bytes to 32,768. Replay bookkeeping is capped at 1,000 frame identities per hook lifetime, after which it falls back rather than evicting protection. The fixed official endpoint prevents configurable endpoint or redirect credential leakage. Errors and keys are never returned, logged, or placed in annotations.

The 0.95 threshold is a conservative, configurable fallback policy, **not measured correctness or calibrated application accuracy**. TypeSafe's [confidence explanation](https://docs.typesafe.ai/confidence.md) distinguishes confidence as a distribution statistic from the probability assigned to an option. The adapter thresholds selected probability; no threshold has been calibrated on OpenScene tasks. Mock tests verify protocol/branch behavior only. No paid/live call, real account validation, model download, or empirical judgment-quality evaluation has been performed.

Desktop window observation is platform-bound. Mobile cannot use this desktop window driver; it must retain its existing model path and must not simulate observation or expose desktop credentials. No shared editing rule or mobile model is changed by this main-only adapter.

## Verification evidence

Mock registered-tool JSON-string integration exercises default off, sufficient, reobserve, uncertainty, thrown-hook and absent-hook branches, including image preservation/withholding. Native Node fetch tests use only a loopback HTTP server with fake keys and the actual CuaDriver lease: streamed-body input exclusion, Stop cancellation, and noncooperative transport retaining Stop until settlement. These are protocol/lifetime checks, not an authenticated TypeSafe test or an Electron GUI test.
